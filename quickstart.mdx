---

In this guide you will build a sandboxed JavaScript environment that calls PHP capabilities you define. By the end you will have loaded a guest engine, registered a typed PHP function as a capability, run untrusted guest code that calls it, read captured output, handled guest exceptions, and inspected the generated type declaration — all in a single PHP file.

<Steps>
  <Step title="Load a guest engine">
    Create a `Terrarium` instance by pointing it at a `*_guest.wasm` file. Set resource limits to contain untrusted code:

    ```php
    require 'vendor/autoload.php';

    use Terrarium\Terrarium;

    $wasm = new Terrarium(
        'quickjs_guest.wasm',
        timeoutMs: 500,
        memoryLimit: 32 << 20,   // 32 MB
    );
    ```

    The guest language is decided entirely by which `.wasm` you load. Swap `quickjs_guest.wasm` for `boa_guest.wasm`, `rustpython_guest.wasm`, `php_guest.wasm`, or `typescript_guest.wasm` and nothing else in the host code changes.
  </Step>

  <Step title="Register capabilities">
    Expose PHP functions to the guest with `register()`. Use a dotted name; the guest calls it exactly as written — `user.fetch(...)` — with no synthetic root. Types are inferred from the PHP signature and PHPDoc, including nested `array{…}` shapes:

    ```php
    $wasm->register('user.fetch',
        /**
         * Fetch a user by ID.
         * @return array{name: string, roles: string[]}
         */
        fn (int $id): array => ['name' => 'Ada', 'roles' => ['admin', 'dev']]);
    ```

    The capability allowlist is the entire trust boundary. The guest can only call functions you explicitly passed to `register()`. It has no access to your filesystem, database, network, or any other PHP state.
  </Step>

  <Step title="Run guest code">
    Call `eval()` with any guest-language source string. The result is marshalled back to a PHP value:

    ```php
    $result = $wasm->eval('user.fetch(42).roles.length');
    echo $result;   // 2
    ```

    The guest engine runs entirely inside WebAssembly. Even a memory-corruption bug in the engine cannot reach your PHP process.
  </Step>

  <Step title="Inspect captured output">
    Anything the guest writes via `console.log` (JavaScript/TypeScript) or `print` (Python) / `echo` (PHP) is captured into a per-`eval` buffer. Read it with `output()` after the call:

    ```php
    $wasm->eval('console.log("hello from the sandbox"); "done"');
    echo $wasm->output();   // "hello from the sandbox"
    ```

    Output is preserved even when the `eval` throws an exception, so anything printed before a crash is still readable.
  </Step>

  <Step title="Handle errors">
    Guest failures surface as typed exceptions in the `Terrarium\Exception` family. Catch the specific type you expect, or the base `Exception` for everything:

    ```php
    use Terrarium\GuestException;
    use Terrarium\TimeoutException;
    use Terrarium\MemoryException;
    use Terrarium\Exception as TerrariumException;

    try {
        $wasm->eval('user.fetch("not-an-int")');
    } catch (GuestException $e) {
        // A guest-side error: a thrown JS exception, Python traceback,
        // or TypeScript type error. Message format: "Type: message (line N)"
        echo $e->getMessage();
    } catch (TimeoutException $e) {
        // Wall-clock budget (timeoutMs) or fuel limit exhausted.
        echo 'Guest timed out: ', $e->getMessage();
    } catch (MemoryException $e) {
        // Guest exceeded the memoryLimit.
        echo 'Guest ran out of memory: ', $e->getMessage();
    } catch (TerrariumException $e) {
        // Catch-all for any other Terrarium error.
        echo 'Terrarium error: ', $e->getMessage();
    }
    ```
  </Step>

  <Step title="Get the type declaration">
    Call `types()` to emit the generated type declaration for your registered SDK, inferred directly from the PHP signatures and PHPDoc:

    ```php
    // TypeScript .d.ts — what the TypeScript guest type-checks against
    echo $wasm->types('dts');

    // Python .pyi stub — TypedDicts derived from your PHP array shapes
    echo $wasm->types('pyi');

    // PHP stub — namespace classes; the PHP guest's view of the SDK
    echo $wasm->types('php');
    ```

    Share the appropriate stub with the author writing guest code so their editor provides autocompletion and inline type errors without you maintaining a separate schema.
  </Step>
</Steps>

<Note>
  `check()` validates guest source **without running it** and returns every diagnostic as structured data — `[]` means it passed. Nothing executes: no capability fires and `output()` is untouched. Use it to lint untrusted source before committing to a full `eval()`. See the [eval / check / analyze reference](/api/eval-check-analyze).
</Note>

## Running multiple languages

The four-language example below registers an identical SDK once and evaluates the same program in every bundled guest engine. Only the `.wasm` path changes:

```php
require 'vendor/autoload.php';

use Terrarium\Terrarium;

$wasm = fn (string $f) => __DIR__ . "/guests/$f";

// Register the same SDK on any Terrarium instance.
function wire(Terrarium $g): void
{
    $g->register('math.add', fn (int $a, int $b): int => $a + $b);
    $g->register('user.fetch',
        /** @return array{name: string, roles: string[]} */
        fn (int $id): array => ['name' => 'Ada', 'roles' => ['admin', 'dev']]);
    $g->register('log.info', fn (string $m): void => print($m . PHP_EOL));
}

// JavaScript source
$jsSrc = <<<'JS'
    const u = user.fetch(42);
    log.info(`fetched ${u.name}`);
    `${u.name} / roles=${u.roles.length} / add=${math.add(2, 3)}`
    JS;

// Python source
$pySrc = <<<'PY'
    u = user.fetch(42)
    log.info("fetched " + u["name"])
    "%s / roles=%d / add=%d" % (u["name"], len(u["roles"]), math.add(2, 3))
    PY;

// PHP-in-PHP source (SDK exposed as proxy objects)
$phpSrc = <<<'GUEST'
    $u = $user->fetch(42);
    $log->info("fetched " . $u["name"]);
    return sprintf("%s / roles=%d / add=%d", $u["name"], count($u["roles"]), $math->add(2, 3));
    GUEST;

// Run the same program in all four engines — only the .wasm path differs.
foreach ([
    'QuickJS-ng (JavaScript)' => [$wasm('quickjs_guest.wasm'), $jsSrc, 2000],
    'Boa (JavaScript)'        => [$wasm('boa_guest.wasm'), $jsSrc, 2000],
    'RustPython (Python)'     => [$wasm('rustpython_guest.wasm'), $pySrc, 5000],
    'php-src (PHP-in-PHP)'    => [$wasm('php_guest.wasm'), $phpSrc, 5000],
] as $engine => [$path, $src, $budget]) {
    echo "=== $engine ===\n";
    $g = new Terrarium($path, timeoutMs: $budget);
    wire($g);
    echo $g->eval($src), "\n\n";
}
```

<Tip>
  For code you write yourself or want to validate rigorously, use the TypeScript guest. It runs the real `tsc` inside the sandbox and type-checks every `eval()` against the `.d.ts` generated from your PHP SDK before executing anything — a wrong argument type or missing property is caught before a single line of guest code runs. See [TypeScript guest](/guides/typescript-guest).
</Tip>
