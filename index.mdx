Terrarium lets you safely execute untrusted guest code — JavaScript, TypeScript, Python, or PHP — directly from PHP, with WebAssembly as the hard, in-process isolation boundary. You define what the guest can do by registering typed PHP functions as capabilities. The guest can call only those functions, nothing else.

## How it works

You write a typed PHP SDK by registering ordinary PHP closures. The guest — a real language engine compiled to WebAssembly — runs in a sandboxed linear memory and calls those capabilities by their dotted names. Types are inferred from your PHP signatures and PHPDoc, then emitted as `.d.ts`, `.pyi`, or `.php` stubs for guest authors.

```php
use Terrarium\Terrarium;

$wasm = new Terrarium('quickjs_guest.wasm', timeoutMs: 500, memoryLimit: 32 << 20);

$wasm->register('user.fetch',
    /** @return array{name: string, roles: string[]} */
    fn (int $id): array => ['name' => 'Ada', 'roles' => ['admin', 'dev']]);

echo $wasm->eval('user.fetch(42).roles.length');  // => 2
echo $wasm->types('dts');  // a typed .d.ts of your registered SDK
```

Swap `quickjs_guest.wasm` for `boa_guest.wasm`, `rustpython_guest.wasm`, `php_guest.wasm`, or `typescript_guest.wasm` and your host code is unchanged.

<Steps>
  <Step title="Install the extension">
    Download the `.so`/`.dylib` matching your PHP version and architecture, or install via Composer. See [Installation](/installation).
  </Step>
  <Step title="Register your SDK">
    Call `register()` with typed PHP closures. Type signatures and PHPDoc are all you need — no separate schema files.
  </Step>
  <Step title="Run guest code">
    Call `eval()` to execute source in the sandbox. Guest errors surface as typed PHP exceptions; printed output is captured separately with `output()`.
  </Step>
  <Step title="Validate statically">
    Use `check()` to validate source without executing it, or `analyze()` to extract JSON Schemas from TypeScript type arguments.
  </Step>
</Steps>
